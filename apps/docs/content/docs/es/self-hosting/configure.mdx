---
title: Configurar tu instancia
description: Activa el correo, el almacenamiento de archivos, las funciones de IA y los datos de mercado, y controla quién puede registrarse.
---

Toda la configuración está en el archivo `.env`, junto al `docker-compose.yml`, comentada sección por sección. Después de editarlo, aplica los cambios con:

```sh
docker compose up -d
```

## Correo

Indica un servidor SMTP:

```sh
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USER=...
SMTP_PASSWORD=...
EMAIL_FROM=money@example.com
```

O define `RESEND_API_KEY` para usar Resend. Para probar sin un proveedor real, usa el Mailpit incluido: añade `mail` a `COMPOSE_PROFILES`, define `SMTP_HOST=mailpit` y `SMTP_PORT=1025`, ejecuta `docker compose up -d` y lee los correos en http://localhost:8025.

Sin un proveedor configurado, la API escribe cada mensaje en su registro y el worker no envía recordatorios en segundo plano (recordatorios de pago de la tarjeta, caducidad de tokens de API). Los recordatorios de pago de la tarjeta salen unos días antes del vencimiento de un extracto: define `CREDIT_CARD_DUE_REMINDER_DAYS` en el worker para cambiar la antelación (3 de forma predeterminada, un número entero de días).

## Almacenamiento de archivos

Las importaciones CSV y las copias de recibos necesitan almacenamiento compatible con S3. Para usar el almacenamiento incluido ([SeaweedFS](https://github.com/seaweedfs/seaweedfs)), define estos valores en `.env` y ejecuta `docker compose up -d`:

```sh
COMPOSE_PROFILES=storage
AWS_ACCESS_KEY_ID=elige-un-usuario
AWS_SECRET_ACCESS_KEY=elige-una-contrasena-larga
S3_ENDPOINT=http://storage:8333
S3_PUBLIC_ENDPOINT=http://localhost:9000
S3_BUCKET=wondermoney
```

Las dos claves pasan a ser las credenciales del almacenamiento, que no arranca sin ellas. `S3_PUBLIC_ENDPOINT` es la dirección que usan los navegadores para llegar al almacenamiento; detrás de un proxy, dale su propio nombre con HTTPS que redirija al puerto 9000. Cualquier servicio compatible con S3 también funciona, como Cloudflare R2, Backblaze B2 o AWS S3. Los adjuntos de transacciones usan el mismo almacenamiento: sin él, la sección de adjuntos queda oculta y sus endpoints responden 503.

## Funciones de IA

La lectura de recibos, el mapeo de columnas CSV, la importación de extractos en PDF, la categorización de transacciones, el resumen mensual y el asistente funcionan con cualquier endpoint compatible con OpenAI: OpenAI, OpenRouter, o un modelo ejecutado localmente con Ollama, LM Studio o vLLM.

```sh
AI_BASE_URL=http://host.docker.internal:11434/v1
AI_MODEL=llama3.1
```

Define `AI_API_KEY` cuando el endpoint necesite una clave. Para usar otro modelo en una función concreta, define `AI_MODEL_<FUNCIÓN>`; por ejemplo, la lectura de recibos necesita un modelo que lea imágenes, definido con `AI_MODEL_OCR`.

Para usar Anthropic con tu propia clave de API, elígela explícitamente:

```sh
AI_PROVIDER=anthropic
ANTHROPIC_API_KEY=sk-ant-...
AI_MODEL=claude-sonnet-4-5
```

`AI_MODEL`, o `AI_MODEL_<FUNCIÓN>` para una función, es obligatorio: no hay modelo predeterminado. La lectura de recibos necesita un modelo que lea imágenes, así que define `AI_MODEL_OCR` si tu modelo predeterminado no lo hace. Anthropic tiene prioridad sobre `AI_BASE_URL`, pero una configuración completa de Azure sigue teniendo precedencia.

La [importación de extractos en PDF](/es/docs/accounts-transactions/import-pdf-statements) envía cada página del extracto al modelo como imagen, así que necesita un modelo que lea imágenes. En un endpoint compatible con OpenAI queda desactivada hasta que indiques uno con `AI_MODEL_STATEMENT_IMPORT`; `AI_MODEL` no se usa para ella, porque un modelo local predeterminado a menudo solo lee texto. En Anthropic usa `AI_MODEL_STATEMENT_IMPORT`, o `AI_MODEL` cuando está vacío. La aplicación le dice a la persona cuál es el proveedor antes de enviar ninguna página: Anthropic o Azure OpenAI por su nombre, un endpoint compatible con OpenAI como el proveedor de IA configurado en el servidor. La dirección del endpoint nunca se muestra, y `GET /v1/instance` indica solo el tipo de proveedor.

| Ajuste | Qué hace |
|---|---|
| `AI_MODEL_STATEMENT_IMPORT` | El modelo que lee los extractos en PDF. Obligatorio en un endpoint compatible con OpenAI |
| `AI_DAILY_LIMIT_STATEMENT_IMPORT` | Extractos en PDF que un hogar puede importar al día; cada extracto cuenta como uno, tenga las páginas que tenga. Vacío significa sin límite |
| `STATEMENT_IMPORT_MAX_BYTES` | El PDF más grande que se acepta, en bytes. Por defecto `10485760` (10 MB) |
| `STATEMENT_IMPORT_MAX_PAGES` | El máximo de páginas de un extracto. Cada página es una petición al modelo, así que también limita lo que cuesta un extracto. Por defecto `20` |

Define los dos límites en la API y en el worker; un valor que no sea un número entero positivo impide que arranquen.

Si el registro está abierto y pagas por el modelo, define `AI_REQUIRES_VERIFIED_EMAIL=true`. Las cuentas creadas con correo y contraseña reciben entonces un enlace de verificación por correo, y tienen que seguirlo antes de poder usar el asistente, la lectura de recibos, el mapeo de columnas con IA o la importación de extractos en PDF. Las cuentas de Google y Apple cuentan como verificadas. Necesita el correo configurado.

Para limitar lo que cada hogar puede gastar en el modelo al día, define `AI_DAILY_LIMIT_ASSISTANT` (mensajes al asistente), `AI_DAILY_LIMIT_OCR` (lecturas de recibos) y `AI_DAILY_LIMIT_CSV_MAPPING` (importaciones CSV que mapea el modelo). Los miembros de un hogar comparten el límite, que se reinicia a medianoche UTC. Déjalos vacíos para no tener límite. Cuando un hogar llega a un límite, la aplicación lo indica hasta el día siguiente; las importaciones CSV siguen funcionando, con las columnas mapeadas a mano.

## Datos de mercado

Define `EODHD_API_KEY` para activar la búsqueda de tickers, las cotizaciones en tiempo real y el módulo de Mercados Financieros.

## Logotipos de comercios

Los logotipos de comercios están desactivados por defecto. Cada comercio muestra entonces la primera letra de su nombre en un círculo de color, y nada sobre los comercios de tus usuarios sale del servidor.

Define `MERCHANT_LOGO_URL_TEMPLATE` con la dirección de un servicio de logotipos, con `{domain}` donde va el dominio del sitio web del comercio, por ejemplo `https://logos.example.com/{domain}.png`. Debe ser una dirección `https`, y `{domain}` debe ir después del host; cualquier otro valor impide que la API arranque. Defínelo en la API.

Cuando un miembro añade un sitio web a un comercio, la API pide al servicio el logotipo de ese dominio, lo guarda un día (un dominio sin logotipo, una hora) y lo sirve a las aplicaciones web y móvil desde tu propio servidor. El servicio ve la dirección de tu servidor y el dominio del comercio, como `example.com`. Nunca ve las direcciones, los navegadores, las cuentas ni las transacciones de tus usuarios, y las aplicaciones nunca lo contactan. Elige un servicio cuyas condiciones aceptes para ello, e indícalo en tu política de privacidad.

Una dirección de logotipo que un miembro escriba él mismo tiene prioridad sobre la plantilla. Las aplicaciones cargan esa imagen directamente desde la dirección que eligió el miembro, sin referente, así que ese sitio ve la dirección de cada miembro del hogar que la ve. Solo se aceptan direcciones `https` con un nombre de host.

## Sincronización bancaria

La sincronización bancaria no necesita configuración en el servidor. Cada persona añade su propia clave de aplicación de Enable Banking en la Configuración, así que las credenciales bancarias nunca se comparten entre usuarios.

El worker sincroniza cada conexión bancaria como máximo una vez cada `BANK_SYNC_MIN_INTERVAL_HOURS` horas, 20 por defecto. Según la PSD2, un banco puede limitar el acceso no asistido a cuatro llamadas al día por cuenta, así que defínela en `6` o más para mantenerte dentro de ese límite. Una sincronización fallida espera el mismo intervalo antes del siguiente intento. Defínela en el worker; un valor que no sea un número positivo impide que el worker arranque.

## Inicio de sesión con Google

Define `GOOGLE_CLIENT_ID` y `GOOGLE_CLIENT_SECRET` (de un cliente OAuth en Google Cloud, con `<API_URL>/api/auth/callback/google` como URI de redirección autorizado) para mostrar "Continuar con Google" en las páginas de inicio de sesión y de registro. Sin ambos, el botón queda oculto.

## Inicio de sesión único (OIDC)

Inicia sesión a través de tu propio proveedor de identidad, como Authentik o Keycloak: las páginas de inicio de sesión y de registro, en la web y en la aplicación móvil, muestran entonces `Iniciar sesión con <nombre>`. [Inicio de sesión único](/es/docs/self-hosting/single-sign-on) explica cómo configurar el proveedor.

| Ajuste | Qué hace |
|---|---|
| `OIDC_ISSUER`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET` | La URL del emisor del proveedor (HTTPS) y el cliente que registraste allí, con `<API_URL>/api/auth/callback/oidc` como URI de redirección. Los tres activan el inicio de sesión único juntos; cualquier otro ajuste `OIDC_` sin ellos impide que la API arranque |
| `OIDC_DISPLAY_NAME` | El nombre del botón. Por defecto, `SSO` |
| `OIDC_SCOPES` | Los ámbitos que se piden, separados por espacios; debe incluir `openid`. Por defecto, `openid email profile` |
| `OIDC_GROUPS_CLAIM` | La claim que lista los grupos de la persona. Por defecto, `groups` |
| `OIDC_ALLOWED_GROUPS` | Grupos separados por comas. Si se define, solo sus miembros (y los miembros de los grupos de administración) pueden iniciar sesión |
| `OIDC_ADMIN_GROUPS` | Grupos separados por comas cuyos miembros son administradores de la instancia. Se comprueba en cada inicio de sesión, así que salir del grupo retira la administración |
| `OIDC_AUTO_SIGNUP` | `true` crea la cuenta en el primer inicio de sesión a través del proveedor aunque `SIGNUP_MODE` sea `invite` o `closed`. El registro con contraseña sigue a `SIGNUP_MODE` |
| `OIDC_ONLY` | `true` desactiva el inicio de sesión, el registro y el restablecimiento con contraseña, y los oculta en las aplicaciones. Las llaves de acceso siguen funcionando |
| `OIDC_TRUST_IDP_MFA` | `true` omite el código del autenticador de WonderMoney tras un inicio de sesión a través del proveedor. Defínelo solo si el propio proveedor exige un segundo factor |
| `OIDC_ALLOW_UNVERIFIED_EMAIL` | `true` acepta una dirección de correo que el proveedor no ha verificado. Desactivado por defecto; una cuenta así nunca se vincula a una existente |

`GET /v1/instance` indica `features.oidc: { "name": "<OIDC_DISPLAY_NAME>" }` y, con `OIDC_ONLY`, `features.passwordSignIn: false`.

## Llaves de acceso

Las llaves de acceso (passkeys) no necesitan ninguna variable de entorno. Pertenecen al dominio de `APP_URL`, la dirección de la aplicación web, y el navegador solo las ofrece en ese dominio. Funciona igual tanto si la aplicación web y la API comparten un dominio como si usan dos, como `money.example.com` y `api.money.example.com`.

Los navegadores solo permiten llaves de acceso por HTTPS, o en `http://localhost`. Una dirección IP como `http://192.168.1.10:3000` no funciona: da a la aplicación web un dominio con HTTPS (consulta [HTTPS y dominios](/es/docs/self-hosting/https-and-domains)).

Si la aplicación web pasa a otro dominio, las llaves de acceso existentes dejan de funcionar y tus usuarios tienen que volver a añadirlas. Sus contraseñas siguen funcionando. `GET /v1/instance` informa de `features.passkey: true`.

## Tu instancia

| Ajuste | Qué hace |
|---|---|
| `INSTANCE_NAME` | El nombre de tu instancia. La aplicación web lo muestra en los títulos de las pestañas del navegador, en las vistas previas de enlaces y en las páginas de inicio de sesión y registro, y en lugar del logotipo de WonderMoney cuando lo cambias. Cada correo lo usa en el asunto, el texto y la firma, y como nombre del remitente si `EMAIL_FROM_NAME` no está definido; las aplicaciones de autenticación lo muestran como etiqueta. La aplicación web lo lee de la API, así que defínelo solo en la API; un cambio aparece en la aplicación web en un máximo de cinco minutos |
| `SIGNUP_MODE` | `open`, `invite` o `closed` (consulta [Instalar](/es/docs/self-hosting/install)) |
| `SUPPORT_EMAIL` | El buzón del formulario de contacto, de las alertas de cuenta y de los comentarios desde la aplicación, y la dirección de soporte que muestra la aplicación; déjalo vacío para desactivarlos y ocultar los enlaces de soporte. El formulario "Compartir comentarios" también necesita el correo configurado; sin él, el formulario se oculta |
| `SPONSOR_URL` | Una página donde tus usuarios pueden contribuir a mantener la instancia (Open Collective, GitHub Sponsors, ...). Las preguntas frecuentes de la aplicación web la enlazan cuando está definida |
| `NEXT_PUBLIC_TERMS_URL`, `NEXT_PUBLIC_PRIVACY_URL` | Tus páginas legales, enlazadas desde la página de registro cuando ambas están definidas |
| `PRIVACY_POLICY_URL` | Tu política de privacidad, enlazada desde el pie de los correos. `{lang}` se sustituye por el idioma del destinatario (`en` o `pt`), por ejemplo `https://example.com/{lang}/privacy`. Por defecto, apunta a los ajustes de privacidad de la aplicación |
| `MCP_ENABLED` | El servidor MCP de solo lectura en `POST /v1/mcp`, que permite a un cliente de IA preguntar por las finanzas del propio usuario con un token de API personal con `mcp:read` (consulta [Conectar un cliente de IA](/es/docs/settings-security-privacy/connect-ai-client)). Activado por defecto; define `false` para responder `404` e informar de `features.mcp: false` en `GET /v1/instance` |
| `TRANSFER_MATCH_FX_TOLERANCE` | La diferencia aceptada entre los dos lados de una transferencia entre cuentas en monedas distintas, después de convertir el importe que salió al tipo de cambio de ese día, como fracción del importe que llegó: `0.02` (por defecto) es un 2 por ciento. Súbela si el margen de cambio y las comisiones de tu banco son mayores; como máximo `0.25`. Configúrala en la API y en el worker |

## Analítica

Tu instancia no carga analítica ni gestor de etiquetas, ni registra eventos de uso, a menos que los actives. Cada ajuste de abajo activa un servicio, que envía a tu propia cuenta en ese servicio; déjalos vacíos para mantener todo desactivado.

| Ajuste | Qué activa |
|---|---|
| `NEXT_PUBLIC_GTM_ID` | Tu contenedor de Google Tag Manager (`GTM-XXXXXXX`), cargado en todas las páginas de la aplicación web |
| `NEXT_PUBLIC_POSTHOG_KEY` | PostHog en la aplicación web: vistas de página, eventos de uso y grabaciones de sesión, asociados a la dirección de correo de cada usuario |
| `ANALYTICS_OUTBOX_MODE=live` con `POSTHOG_API_KEY` | Eventos de registro, inicio de sesión y sincronización bancaria enviados a PostHog por la API y el worker. Define ambos en la API y en el worker; con el modo desactivado, no se registra ningún evento |

Si activas alguno, informa a tus usuarios en tu política de privacidad (`NEXT_PUBLIC_PRIVACY_URL`) y pide su consentimiento cuando la ley lo exija.

## Qué envía tu instancia

No se envía nada al proyecto WonderMoney. Cada servicio externo que tu instancia puede contactar, y lo que lo activa:

| Servicio | Lo contacta | Se activa con |
|---|---|---|
| Banco Central Europeo | El worker, una vez al día, para descargar los tipos de cambio del euro. No envía datos sobre ti ni sobre tus usuarios | Siempre activo |
| Correo (tu servidor SMTP o Resend) | La API y el worker, para enviar restablecimientos de contraseña, invitaciones y notificaciones | `SMTP_HOST` o `RESEND_API_KEY` |
| IA (tu endpoint compatible con OpenAI o Anthropic) | La API y el worker, con el recibo, las columnas del CSV, las páginas del extracto, las transacciones o los mensajes de chat que necesita la función | `AI_BASE_URL` y `AI_MODEL`, o `AI_PROVIDER=anthropic`, `ANTHROPIC_API_KEY` y `AI_MODEL` |
| Datos de mercado (EODHD) | La API y el worker, con símbolos bursátiles, no datos de usuarios | `EODHD_API_KEY` |
| Logotipos de comercios (el servicio que elijas) | La API, con el dominio del sitio web de un comercio, no datos de usuarios ([Logotipos de comercios](#logotipos-de-comercios)) | `MERCHANT_LOGO_URL_TEMPLATE` |
| Almacenamiento de archivos (tu almacenamiento compatible con S3) | La API y los navegadores, para importaciones de CSV y copias de recibos | `S3_ENDPOINT` y `S3_BUCKET` |
| Copias de seguridad fuera del servidor (tu destino de rclone) | El servicio `backup-offsite`, una vez al día, con las copias de la base de datos y de los archivos | El perfil `backup-offsite` y `BACKUP_DESTINATION` ([Actualizaciones y copias de seguridad](/es/docs/self-hosting/upgrade-and-backup#copias-fuera-del-servidor)) |
| Registro de errores (Sentry) | La API, el worker y la aplicación web, con informes de errores | `SENTRY_DSN` (API y worker), `NEXT_PUBLIC_SENTRY_DSN` (aplicación web) |
| Analítica (Google Tag Manager, PostHog) | Consulta [Analítica](#analítica) | `NEXT_PUBLIC_GTM_ID`, `NEXT_PUBLIC_POSTHOG_KEY`, `ANALYTICS_OUTBOX_MODE=live` |
| Sincronización bancaria (Enable Banking) | La API y el worker, para los usuarios que conectan un banco | La clave de Enable Banking de cada usuario, añadida en Ajustes |
| Inicio de sesión con Google | Los navegadores y la API, cuando un usuario elige "Continuar con Google" | `GOOGLE_CLIENT_ID` y `GOOGLE_CLIENT_SECRET` |
| Tu proveedor de identidad (OIDC) | Los navegadores y la API, cuando un usuario elige `Iniciar sesión con <nombre>`. La API obtiene el documento de descubrimiento y las claves del proveedor, e intercambia el código de inicio de sesión | `OIDC_ISSUER`, `OIDC_CLIENT_ID` y `OIDC_CLIENT_SECRET` |
| reCAPTCHA | Los navegadores en el formulario de contacto, y la aplicación web para comprobar la respuesta | `NEXT_PUBLIC_RECAPTCHA_SITE_KEY` y `RECAPTCHA_SECRET_KEY` |

Los navegadores también cargan los logotipos de bancos y bolsas desde las direcciones guardadas en el catálogo de bancos y activos, y el logotipo de un comercio desde la dirección que un miembro escribió para él. La aplicación móvil no envía analítica ni informes de errores mientras está conectada a tu servidor.
