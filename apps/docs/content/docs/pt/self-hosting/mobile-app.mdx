---
title: Usar a aplicação móvel com o teu servidor
description: Liga a aplicação WonderMoney para iOS e Android ao teu próprio servidor.
---

A aplicação WonderMoney funciona com qualquer servidor WonderMoney, não apenas com o wonder.money.

## Ligar a aplicação com um código QR

A forma mais rápida de ligar a aplicação é ler um código a partir da aplicação web do teu servidor, sem escrever nada no teclado do telemóvel.

1. Na aplicação web, abre **Definições → Segurança**.
2. Em **Ligar a aplicação móvel**, toca em **Mostrar código QR**.
3. No ecrã de início de sessão da aplicação, toca em **Ler código QR** e aponta a câmara para o código.

O código funciona uma vez e expira ao fim de dois minutos; se expirar, mostra um novo. Se a autenticação de dois fatores estiver ativa na tua conta, introduz o código do autenticador na web antes de o QR aparecer — o telemóvel não o pede, porque a sessão web já o validou.

Também podes ler o código com a aplicação de câmara do telemóvel: o código é uma ligação `wondermoney://` que abre a aplicação. A aplicação verifica o endereço antes de ligar, por isso um código de outra aplicação ou de um servidor que não seja WonderMoney é recusado.

## Ligar a aplicação manualmente

1. Abre a aplicação e vai ao ecrã de início de sessão.
2. Toca em **Usar outro servidor**.
3. Introduz o endereço do teu servidor, o `API_URL` do teu `.env` — com um só domínio, o mesmo endereço da aplicação web, por exemplo `money.example.com`.
4. Toca em **Ligar** e inicia sessão com a tua conta nesse servidor.

A aplicação verifica o endereço antes de o guardar. Se não conseguir chegar ao servidor, se não for um servidor WonderMoney ou se precisar de uma versão mais recente da aplicação, a aplicação avisa-te e mantém o servidor anterior.

## Dispositivos ligados

**Definições → Segurança → Dispositivos** lista os telemóveis ligados à tua conta, com a última vez que cada um foi visto. **Revogar** termina a sessão desse telemóvel de imediato; tem de ler um novo código para se ligar outra vez.

## Notificações push

A aplicação pode mostrar alertas de orçamento, lembretes de pagamento do cartão e alertas de ligações bancárias como notificações push, depois de o teu servidor ligar o push (`PUSH_ENABLED=true`, consulta [Configurar](/pt/docs/self-hosting/configure#notificações-push)). Abre **Definições → Notificações** na aplicação: cada categoria de push fica desligada até a ligares, e o telemóvel pede autorização na primeira vez que o fazes. **Enviar notificação de teste** verifica o caminho todo. Tocar numa notificação abre o ecrã a que ela se refere. Terminar a sessão remove o telemóvel, tal como revogá-lo em **Dispositivos**.

### Que versões da aplicação o teu servidor consegue alcançar

As notificações passam pelo serviço de push da Expo. O token de push de um telemóvel pertence ao projeto Expo a partir do qual a aplicação foi compilada, e é esse projeto que guarda as credenciais de push da Apple e da Google. Na aplicação WonderMoney publicada, esse é o projeto dos responsáveis pelo WonderMoney, não o teu.

Por predefinição, a Expo aceita um pedido de push para um token sem verificar quem o envia. O dono do projeto pode ligar a segurança reforçada das notificações push e, a partir daí, a Expo recusa os pedidos de push que não tragam um token de acesso válido para esse projeto. Por isso, o teu servidor só alcança os telemóveis com a aplicação publicada enquanto esse projeto mantiver a segurança reforçada desligada, ou se o dono te der um token de acesso para definires como `EXPO_ACCESS_TOKEN`. Qualquer das duas coisas pode mudar sem aviso.

Para não dependeres disso, compila a aplicação a partir do código com o teu próprio projeto Expo e as tuas próprias credenciais de push da Apple e do Firebase (`apps/mobile/README.md`, "EAS configuration"). O teu servidor envia então para a tua versão; define `EXPO_ACCESS_TOKEN` se ligares a segurança reforçada na tua conta Expo.

## Chaves de acesso

Uma chave de acesso pertence ao domínio da tua aplicação web (o anfitrião do `APP_URL`), e um telemóvel só a oferece a uma aplicação quando esse domínio garante a aplicação e a aplicação foi compilada para a pedir. A aplicação WonderMoney publicada é compilada apenas para o wonder.money. No teu servidor, oculta **Iniciar sessão com uma chave de acesso** e **Adicionar uma chave de acesso**, e as pessoas iniciam sessão com a palavra-passe, a Google, a Apple ou o início de sessão único. As chaves de acesso continuam a funcionar na tua aplicação web, e a aplicação continua a listá-las e a poder eliminá-las.

Para usares chaves de acesso na aplicação com o teu próprio servidor, compila a aplicação a partir do código (`apps/mobile/README.md`, "Passkeys") e define:

| Onde | Variável | Valor |
| --- | --- | --- |
| Compilação da aplicação | `WONDERMONEY_PASSKEY_DOMAINS` | O domínio da tua aplicação web, por exemplo `money.example.com`. No iOS, o App ID precisa da capacidade Associated Domains. |
| Aplicação web | `IOS_APP_TEAM_ID`, `IOS_APP_BUNDLE_ID` | O ID da tua equipa Apple Developer e o bundle ID da aplicação. A aplicação web serve-os como `/.well-known/apple-app-site-association`. |
| Aplicação web | `ANDROID_APP_PACKAGE`, `ANDROID_APP_CERT_SHA256` | O nome do pacote da aplicação e as impressões digitais SHA-256 dos certificados de assinatura, separadas por vírgulas (`AB:CD:…`, como o `keytool` ou a Play Console as mostram). A aplicação web serve-os como `/.well-known/assetlinks.json`. |
| API | `ANDROID_APP_CERT_SHA256` | As mesmas impressões digitais. O Android indica que uma chave de acesso de uma aplicação vem de `android:apk-key-hash:` e do hash do certificado, não do teu endereço web, por isso a API só aceita essa origem para estes certificados. |

Com o Docker Compose, ficam todas no `.env`. Enquanto não estiverem definidas, os dois endereços `/.well-known` respondem 404 e nada muda. Mantém o `APP_URL` na porta HTTPS predefinida: o iOS indica que as chaves de acesso da aplicação vêm de `https://` e do domínio, sem porta.

## Requisitos

- O telemóvel tem de conseguir chegar à API. Na prática, isso significa HTTPS num domínio público; consulta [HTTPS e domínios](/pt/docs/self-hosting/https-and-domains).
- As funcionalidades que o teu servidor não configurou, como a leitura de recibos ou os dados de mercado, também ficam ocultas na aplicação.

## Voltar ao wonder.money

No ecrã de início de sessão, toca em **Usar o servidor predefinido**.
