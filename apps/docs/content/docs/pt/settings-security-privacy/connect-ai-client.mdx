---
title: Ligar um cliente de IA
description: Permite que o ChatGPT, o Claude Desktop, o Cursor ou outro cliente MCP pergunte sobre as tuas próprias finanças, só de leitura.
---

O WonderMoney tem um servidor [Model Context Protocol](https://modelcontextprotocol.io) (MCP) só de leitura. Um cliente MCP como o Claude Desktop, o Cursor ou o VS Code pode perguntar-lhe pelas tuas contas, despesas, orçamentos, objetivos, património líquido e portefólio, e responder no próprio chat do cliente.

O servidor está em `POST /v1/mcp` na tua API. Não é uma conta separada e não tem ferramentas de escrita: pode ler e, se o permitires, propor uma alteração para confirmares. Nunca altera nada sozinho.

## O que o cliente consegue ver

O cliente vê exatamente o que tu vês:

- As contas, transações, orçamentos, categorias, objetivos e portefólios partilhados do agregado.
- As tuas contas privadas e as contas privadas partilhadas contigo, e **não** as contas privadas de outro membro do agregado que estão ocultas para ti.
- Nunca os dados de outro agregado.

Cada ferramenta recebe a tua identidade a partir do token, ou da ligação OAuth que autorizaste, por isso aplicam-se aqui as mesmas regras de privacidade da aplicação.

## O que o cliente consegue fazer

O cliente pode chamar estas ferramentas só de leitura:

- `get_account_balance_summary`, `list_accounts`, `get_net_worth_summary`
- `get_cashflow_summary`, `get_spending_by_category`, `get_spending_trend`, `get_large_transactions_summary`
- `search_transactions` (intervalo de datas, conta, categoria, intervalo de montantes, até 100 linhas)
- `get_budget_status`, `compare_budget_periods`, `list_budgets`, `list_categories`
- `get_goal_progress_summary`, `get_recurring_payments_summary`
- `get_portfolio_summary`, `get_portfolio_income_summary`
- `get_insights`

Não pode criar, alterar nem apagar nada, e não chega ao agregado, às ligações bancárias, às exportações nem à gestão de tokens.

## Propostas

Com o âmbito de propostas (`mcp:propose`), o cliente também pode chamar `propose_categorize_transactions`, `propose_mark_transactions_reviewed` e `propose_update_transaction_note`. Cada uma verifica que todas as transações são transações que consegues ver e prepara uma proposta; não altera a transação. A proposta fica em **Definições > Assistente > Alterações pendentes** (e em **Mais > Alterações pendentes** no telemóvel) até a aplicares ou dispensares, e expira ao fim de sete dias. O cliente não a pode aplicar, nem nenhum token de API. Vê [Definições do assistente](/pt/docs/settings-security-privacy/assistant-settings#propostas-e-alterações-pendentes).

## Criar um token

1. Abre **Definições → Tokens de API**.
2. Em **Ligar um cliente de IA**, seleciona **Criar um token de cliente de IA**.
3. Copia o token imediatamente. Só é mostrado uma vez.

O atalho cria um token chamado "AI client" com o âmbito **Cliente de IA (MCP)** e uma validade de 90 dias. Se usares autenticação de dois fatores, introduz primeiro o código do autenticador. Para acrescentar o âmbito de propostas, marca primeiro **Deixar o cliente propor alterações para eu confirmar**. Também podes criar o token à mão no formulário acima, escolhendo os mesmos âmbitos.

Os âmbitos `mcp:read` e `mcp:propose` chegam apenas ao endpoint MCP: `mcp:read` dá as ferramentas só de leitura e `mcp:propose` as ferramentas de propostas. Não dão acesso às rotas de dados normais, e um token `read` não chega ao MCP: são credenciais separadas de propósito.

## Configuração do cliente

O Claude Desktop liga-se a um servidor MCP remoto com o `mcp-remote`. Acrescenta isto ao `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "wondermoney": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://api.example.com/v1/mcp",
        "--header",
        "Authorization: Bearer <your-token>"
      ]
    }
  }
}
```

O Cursor e outros clientes que falam Streamable HTTP diretamente usam a URL e o cabeçalho:

```json
{
  "mcpServers": {
    "wondermoney": {
      "url": "https://api.example.com/v1/mcp",
      "headers": {
        "Authorization": "Bearer <your-token>"
      }
    }
  }
}
```

Substitui o endereço da API pelo teu e `<your-token>` pelo valor que copiaste. O endpoint não guarda estado: o cliente envia o token em cada pedido e não há sessão para manter.

## Ligar o ChatGPT

O ChatGPT, e outros clientes que iniciam sessão com OAuth, ligam-se sem token, num servidor que o ofereça (consulta [Auto-hospedagem](#auto-hospedagem)). As definições mostram então **Ligar o ChatGPT** em **Ligar um cliente de IA**.

1. No ChatGPT, adiciona uma app (um conector), indica o endpoint MCP, `https://api.example.com/v1/mcp` com o endereço da tua API, e escolhe OAuth. Se o formulário pedir um ícone (o do ChatGPT aceita um PNG de até 10 KB), descarrega `https://money.example.com/wondermoney-icon.png`, com o endereço da tua app, e carrega-o.
2. O ChatGPT envia-te para o WonderMoney. Inicia sessão, se ainda não o fizeste, com o segundo fator se o usares.
3. A página de consentimento indica o cliente, o endereço para onde te devolve e o teu agregado, e lista o que pode fazer. Seleciona **Autorizar**. Autorizar exige teres iniciado sessão nas últimas 24 horas e, se usares autenticação de dois fatores, o teu código de autenticação, tal como criar um token.

O cliente recebe só acesso de leitura (`mcp:read`): as ferramentas só de leitura acima, nunca as ferramentas de propostas, que continuam a exigir um token pessoal. Fica ligado até o desligares; o token de acesso dura 15 minutos e é renovado sem te voltar a perguntar. Os clientes que autorizaste aparecem em **Ligados com OAuth**, com a última vez que chamaram uma ferramenta.

Confirma o endereço na página de consentimento antes de autorizares: qualquer cliente se pode registar com qualquer nome, e só o endereço para onde te devolve (como `https://chatgpt.com`) diz para onde vai a tua resposta. Um cliente que responde a uma app no teu próprio computador aparece como tal, com um aviso. Os clientes só podem registar endereços `https`, ou `http` em `127.0.0.1` ou `localhost`.

A ligação pertence ao agregado em que estavas quando a autorizaste. Se saíres dele ou entrares noutro, o cliente é desligado.

## Registo de auditoria

Cada chamada a uma ferramenta é escrita no registo de auditoria do assistente com o nome da ferramenta, o token ou o cliente OAuth, e a hora. Os montantes e as descrições nunca são escritos lá. **Definições → Tokens de API → Ligar um cliente de IA** lista as chamadas mais recentes.

## Revogar o acesso

Seleciona **Revogar** ao lado do token em **Definições → Tokens de API**. A revogação é imediata: o pedido seguinte do cliente recebe `401 Unauthorized`. Apaga também a entrada do servidor na configuração do cliente, para que deixe de tentar.

Para um cliente ligado com OAuth, seleciona **Desligar** ao lado dele em **Ligados com OAuth**. Os tokens dele deixam de funcionar de imediato, e o pedido seguinte recebe `401 Unauthorized`. Para o voltares a usar, liga-o de novo a partir do cliente. Alterar ou repor a palavra-passe, e terminar a sessão nos outros dispositivos ou em todos, também desliga todos os clientes OAuth.

O servidor remove um cliente que passou sete dias sem ligação: um que ninguém autorizou nos sete dias depois de se registar, ou um desligado há mais de sete dias. Se o ChatGPT ou outro cliente deixar de se ligar depois disso, remove a app (o conector) no cliente e adiciona-a de novo.

## Limites de utilização

O tráfego MCP usa o orçamento de pedidos do próprio token, e cada token pode fazer um número limitado de chamadas a ferramentas por minuto (60 por omissão). Um cliente que ultrapasse qualquer dos limites recebe um erro e pode tentar novamente em breve. O orçamento é separado da tua sessão do navegador.

## Auto-hospedagem

O servidor está ligado por omissão. Define `MCP_ENABLED=false` na API para o desligar: `POST /v1/mcp` passa a responder `404`, e `GET /v1/instance` reporta `features.mcp: false`, pelo que o painel das definições desaparece. Consulta [Configurar](/pt/docs/self-hosting/configure).

O OAuth, de que o ChatGPT precisa, está desligado por omissão. Define `MCP_OAUTH_ENABLED=true` na API para o oferecer. Precisa de um `API_URL` com `https`, e permite que qualquer cliente se registe, como os clientes MCP esperam; cada um continua a precisar do consentimento de uma pessoa. Com ele ligado, a API serve os documentos de descoberta em `/.well-known/oauth-protected-resource` e `/.well-known/oauth-authorization-server`, e um `401` de `POST /v1/mcp` indica-os ao cliente. Com um só nome de anfitrião, encaminha também `/.well-known/oauth-*` para a API; o proxy incluído já o faz. Se o voltares a desligar, nenhum cliente se consegue ligar nem chamar o servidor com OAuth, e os clientes ligados antes continuam nas definições para que as pessoas os possam desligar.
