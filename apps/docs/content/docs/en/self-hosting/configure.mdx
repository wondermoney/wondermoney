---
title: Configure your instance
description: Turn on email, file storage, AI features and market data, and control who can sign up.
---

All configuration lives in the `.env` file next to `docker-compose.yml`, commented section by section. After editing it, apply the changes with:

```sh
docker compose up -d
```

## Email

Set an SMTP server:

```sh
SMTP_HOST=smtp.example.com
SMTP_PORT=587
SMTP_USER=...
SMTP_PASSWORD=...
EMAIL_FROM=money@example.com
```

Or set `RESEND_API_KEY` to use Resend instead. To test without a real provider, use the bundled Mailpit: add `mail` to `COMPOSE_PROFILES`, set `SMTP_HOST=mailpit` and `SMTP_PORT=1025`, run `docker compose up -d`, and read the mail at http://localhost:8025.

With no provider configured, the API writes each message to its log, and the worker sends no background reminders (card payment reminders, API token expiry). Card payment reminders go out a few days before a statement is due: set `CREDIT_CARD_DUE_REMINDER_DAYS` on the worker to change the lead time (3 by default, a whole number of days).

## File storage

CSV imports and receipt copies need S3-compatible storage. To use the bundled store ([SeaweedFS](https://github.com/seaweedfs/seaweedfs)), set these in `.env` and run `docker compose up -d`:

```sh
COMPOSE_PROFILES=storage
AWS_ACCESS_KEY_ID=choose-a-user
AWS_SECRET_ACCESS_KEY=choose-a-long-password
S3_ENDPOINT=http://storage:8333
S3_PUBLIC_ENDPOINT=http://localhost:9000
S3_BUCKET=wondermoney
```

The two keys become the store's credentials, and it won't start without them. `S3_PUBLIC_ENDPOINT` is the address browsers use to reach the storage; behind a proxy, give it its own HTTPS hostname that forwards to port 9000. Any S3-compatible service works too, such as Cloudflare R2, Backblaze B2 or AWS S3. Transaction attachments use the same storage: without it, the attachments section is hidden and its endpoints answer 503.

## AI features

Receipt scanning, CSV column mapping, PDF statement import, transaction categorisation, the monthly story and the assistant work with any OpenAI-compatible endpoint: OpenAI, OpenRouter, or a model running locally with Ollama, LM Studio or vLLM.

```sh
AI_BASE_URL=http://host.docker.internal:11434/v1
AI_MODEL=llama3.1
```

Set `AI_API_KEY` when the endpoint needs one. To use a different model for one feature, set `AI_MODEL_<FEATURE>`; for example, receipt scanning needs a model that reads images, set with `AI_MODEL_OCR`.

To use Anthropic with your own API key, choose it explicitly:

```sh
AI_PROVIDER=anthropic
ANTHROPIC_API_KEY=sk-ant-...
AI_MODEL=claude-sonnet-4-5
```

`AI_MODEL`, or `AI_MODEL_<FEATURE>` for one feature, is required: there is no built-in default model. Receipt scanning needs a model that reads images, so set `AI_MODEL_OCR` if your default does not. Anthropic wins over `AI_BASE_URL`, but a complete Azure setup still takes precedence.

[PDF statement import](/en/docs/accounts-transactions/import-pdf-statements) sends each page of a statement to the model as an image, so it needs a model that reads images. On an OpenAI-compatible endpoint it stays off until you name one with `AI_MODEL_STATEMENT_IMPORT`; `AI_MODEL` is not used for it, since a default local model often reads text only. On Anthropic it uses `AI_MODEL_STATEMENT_IMPORT`, or `AI_MODEL` when that is empty. The app names the provider to the person before any page is sent: Anthropic or Azure OpenAI by name, an OpenAI-compatible endpoint as the AI provider the server is set up with. The endpoint's address is never shown, and `GET /v1/instance` reports only the provider's family.

| Setting | What it does |
|---|---|
| `AI_MODEL_STATEMENT_IMPORT` | The model that reads PDF statements. Required on an OpenAI-compatible endpoint |
| `AI_DAILY_LIMIT_STATEMENT_IMPORT` | PDF statements a household can import per day; each statement counts as one, however many pages it has. Empty means no limit |
| `STATEMENT_IMPORT_MAX_BYTES` | The largest PDF accepted, in bytes. Defaults to `10485760` (10 MB) |
| `STATEMENT_IMPORT_MAX_PAGES` | The most pages a statement can have. Every page is one request to the model, so this also caps what one statement costs. Defaults to `20` |

Set the two limits on the API and the worker; a value that is not a positive whole number stops them at start-up.

If sign-up is open and you pay for the model, set `AI_REQUIRES_VERIFIED_EMAIL=true`. Accounts that sign up with email and password then get a verification link by email, and need to follow it before they can use the assistant, receipt scanning, AI column mapping or PDF statement import. Google and Apple accounts count as verified. It needs email configured.

To cap what each household can spend on the model per day, set `AI_DAILY_LIMIT_ASSISTANT` (assistant messages), `AI_DAILY_LIMIT_OCR` (receipt scans) and `AI_DAILY_LIMIT_CSV_MAPPING` (CSV imports the model maps). Members of a household share the limit, and it resets at midnight UTC. Leave them empty for no limit. Once a household reaches a limit, the app says so until the next day; CSV imports still work, with the columns mapped by hand.

## Market data

Set `EODHD_API_KEY` to turn on ticker search, live prices and the Financial Markets module.

`MARKET_DATA_PROVIDERS` lists the market-data providers to ask, in order, separated by commas. Empty means `eodhd` alone. When a provider fails or has nothing for a security, the next one in the list is asked, and a feature that no listed provider offers is hidden. An unknown or repeated provider stops the API and the worker at start-up. Set it on both.

| Provider | What it gives | Needs |
|---|---|---|
| `eodhd` | Search, latest prices, daily history, dividends and splits, on most exchanges | `EODHD_API_KEY` |
| `stooq` | The latest daily close and daily history for US, London, Xetra and Tokyo listings and the main US indices. No search, dividends or splits | Nothing |
| `coingecko` | Crypto search, latest prices and up to a year of daily history, for pairs written like `BTC-USD` | Nothing |

`MARKET_DATA_PROVIDERS=eodhd,stooq,coingecko` asks EODHD first and the free providers when it cannot answer. `MARKET_DATA_PROVIDERS=stooq,coingecko` prices holdings without an EODHD key; securities are then found only through CoinGecko's crypto search, so stocks must already be in your catalogue.

Stooq and CoinGecko are outside services with their own terms of use, and they stay off until you list them. Read their terms before you do: you are responsible for following them, including any limits on requests and on commercial use. WonderMoney's hosted service does not use them.

Each stored price records the provider it came from. A holding's price history shows it, and administrators see the providers and the recent prices from each at `GET /v1/admin/market-data/sources`.

## Merchant logos

Merchant logos are off by default. Each merchant then shows the first letter of its name in a colored circle, and nothing about your users' merchants leaves the server.

Set `MERCHANT_LOGO_URL_TEMPLATE` to the address of a logo service, with `{domain}` where the merchant's website domain goes, for example `https://logos.example.com/{domain}.png`. It must be an `https` address, and `{domain}` must come after the host; anything else stops the API at start-up. Set it on the API.

When a member adds a website to a merchant, the API asks the service for that domain's logo, keeps it for a day (a domain with no logo for an hour), and serves it to the web and mobile apps from your own server. The service sees your server's address and the merchant's domain, such as `example.com`. It never sees your users' addresses, browsers, accounts or transactions, and the apps never contact it. Pick a service whose terms you accept for that, and say so in your privacy policy.

A logo address a member types in themselves wins over the template. The apps load that image directly from the address the member chose, without a referrer, so that site sees the address of each household member who views it. Only `https` addresses on a named host are accepted.

## Bank sync

Bank sync needs no server configuration. Each person adds their own Enable Banking application key under Settings, so bank credentials are never shared between users.

The worker syncs each bank connection at most once every `BANK_SYNC_MIN_INTERVAL_HOURS` hours, 20 by default. Under PSD2 a bank may limit unattended access to four calls a day per account, so set it to `6` or more to stay inside that limit. A failed sync waits the same interval before the next try. Set it on the worker; a value that is not a positive number stops the worker at start-up.

## Google sign-in

Set both `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` (from an OAuth client in Google Cloud, with `<API_URL>/api/auth/callback/google` as its authorised redirect URI) to offer "Continue with Google" on the login and sign-up pages. Without both, the button is hidden.

## Single sign-on (OIDC)

Sign in through your own identity provider, such as Authentik or Keycloak: the login and sign-up pages, on the web and in the mobile app, then offer `Sign in with <name>`. [Single sign-on](/en/docs/self-hosting/single-sign-on) walks through setting up the provider.

| Setting | What it does |
|---|---|
| `OIDC_ISSUER`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET` | The provider's issuer URL (HTTPS) and the client you registered there, with `<API_URL>/api/auth/callback/oidc` as its redirect URI. The three turn single sign-on on together; any other `OIDC_` setting without them stops the API at start-up |
| `OIDC_DISPLAY_NAME` | The name on the button. Defaults to `SSO` |
| `OIDC_SCOPES` | Space-separated scopes to ask for; must include `openid`. Defaults to `openid email profile` |
| `OIDC_GROUPS_CLAIM` | The claim that lists the person's groups. Defaults to `groups` |
| `OIDC_ALLOWED_GROUPS` | Comma-separated groups. When set, only their members (and members of the admin groups) may sign in |
| `OIDC_ADMIN_GROUPS` | Comma-separated groups whose members are instance admins. Checked at every sign-in, so leaving the group removes admin |
| `OIDC_AUTO_SIGNUP` | `true` creates an account on the first sign-in through the provider even when `SIGNUP_MODE` is `invite` or `closed`. Password sign-up still follows `SIGNUP_MODE` |
| `OIDC_ONLY` | `true` turns off password sign-in, sign-up and password reset, and hides them in the apps. Passkeys keep working |
| `OIDC_TRUST_IDP_MFA` | `true` skips the WonderMoney authenticator code after a sign-in through the provider. Set it only when the provider requires a second factor itself |
| `OIDC_ALLOW_UNVERIFIED_EMAIL` | `true` accepts an email address the provider has not verified. Off by default; such an account is never linked to an existing one |

`GET /v1/instance` reports `features.oidc: { "name": "<OIDC_DISPLAY_NAME>" }` and, under `OIDC_ONLY`, `features.passwordSignIn: false`.

## Passkeys

Passkeys need no environment variable. They belong to the hostname in `APP_URL`, the web app's address, and the browser only offers them on that hostname. This works the same whether the web app and the API share one hostname or use two, such as `money.example.com` and `api.money.example.com`.

Browsers only allow passkeys over HTTPS, or on `http://localhost`. An IP address such as `http://192.168.1.10:3000` won't work: give the web app a hostname with HTTPS (see [HTTPS and domains](/en/docs/self-hosting/https-and-domains)).

If the web app moves to another hostname, existing passkeys stop working and your users have to add them again. Their passwords still work. `GET /v1/instance` reports `features.passkey: true`.

## Your instance

| Setting | What it does |
|---|---|
| `INSTANCE_NAME` | Your instance's name. The web app shows it in browser tab titles, link previews and the sign-in and sign-up pages, and in place of the WonderMoney logo when you change it. Every email uses it in the subject, copy and sign-off, and as the sender's name unless `EMAIL_FROM_NAME` is set; authenticator apps show it as the label. The web app reads it from the API, so set it on the API only; a change shows up in the web app within five minutes |
| `SIGNUP_MODE` | `open`, `invite` or `closed` (see [Install](/en/docs/self-hosting/install)) |
| `SUPPORT_EMAIL` | The inbox for the contact form, account alerts and in-app feedback, and the support address the app shows; leave empty to turn them off and hide the support links. The "Share Feedback" form also needs email configured; without it the form is hidden |
| `SPONSOR_URL` | A page where your users can chip in towards running the instance (Open Collective, GitHub Sponsors, ...). The web app's FAQ links to it when set |
| `NEXT_PUBLIC_TERMS_URL`, `NEXT_PUBLIC_PRIVACY_URL` | Your legal pages, linked from the sign-up page when both are set |
| `PRIVACY_POLICY_URL` | Your privacy policy, linked from email footers. `{lang}` is replaced with the recipient's language (`en` or `pt`), for example `https://example.com/{lang}/privacy`. Defaults to the app's privacy settings |
| `MCP_ENABLED` | The read-only MCP server at `POST /v1/mcp`, which lets an AI client ask about a user's own finances with a personal API token carrying `mcp:read` (see [Connect an AI client](/en/docs/settings-security-privacy/connect-ai-client)). On by default; set it to `false` to answer `404` and report `features.mcp: false` in `GET /v1/instance` |
| `TRANSFER_MATCH_FX_TOLERANCE` | How far apart the two halves of a transfer between accounts in different currencies may be once the amount that left is converted at that day's exchange rate, as a fraction of the amount that arrived: `0.02` (the default) is 2 percent. Raise it if your bank's exchange margin and fees are larger; at most `0.25`. Set it on the API and the worker |

## Analytics

Your instance loads no analytics or tag manager and records no usage events unless you turn one on. Each setting below switches on one tracker, sending to your own account with that service; leave them empty to keep everything off.

| Setting | What it turns on |
|---|---|
| `NEXT_PUBLIC_GTM_ID` | Your Google Tag Manager container (`GTM-XXXXXXX`), loaded on every page of the web app |
| `NEXT_PUBLIC_POSTHOG_KEY` | PostHog in the web app: page views, usage events and session recordings, linked to each user's email address |
| `ANALYTICS_OUTBOX_MODE=live` with `POSTHOG_API_KEY` | Sign-up, login and bank sync events sent to PostHog by the API and the worker. Set both on the API and the worker; while the mode is off, no events are recorded |

If you turn any of these on, tell your users in your privacy policy (`NEXT_PUBLIC_PRIVACY_URL`), and ask for consent where the law requires it.

## What your instance sends

Nothing is sent to the WonderMoney project. Each outside service your instance can contact, and what switches it on:

| Service | Contacted by | Switched on by |
|---|---|---|
| European Central Bank | The worker, once a day, to download euro exchange rates. It sends no data about you or your users | Always on |
| Email (your SMTP server or Resend) | The API and the worker, to send password resets, invites and notifications | `SMTP_HOST` or `RESEND_API_KEY` |
| AI (your OpenAI-compatible endpoint or Anthropic) | The API and the worker, with the receipt, CSV columns, statement pages, transactions or chat messages the feature needs | `AI_BASE_URL` and `AI_MODEL`, or `AI_PROVIDER=anthropic`, `ANTHROPIC_API_KEY` and `AI_MODEL` |
| Market data (EODHD) | The API and the worker, with ticker symbols, not user data | `EODHD_API_KEY` |
| Market data (Stooq) | The API and the worker, with ticker symbols, not user data | `stooq` in `MARKET_DATA_PROVIDERS` |
| Market data (CoinGecko) | The API and the worker, with coin symbols and search text, not user data | `coingecko` in `MARKET_DATA_PROVIDERS` |
| Merchant logos (the service you choose) | The API, with the domain of a merchant's website, not user data ([Merchant logos](#merchant-logos)) | `MERCHANT_LOGO_URL_TEMPLATE` |
| File storage (your S3-compatible store) | The API and browsers, for CSV imports and receipt copies | `S3_ENDPOINT` and `S3_BUCKET` |
| Off-site backups (your rclone remote) | The `backup-offsite` service, once a day, with the database and file backups | The `backup-offsite` profile and `BACKUP_DESTINATION` ([Updates and backups](/en/docs/self-hosting/upgrade-and-backup#off-site-copies)) |
| Error tracking (Sentry) | The API, the worker and the web app, with error reports | `SENTRY_DSN` (API and worker), `NEXT_PUBLIC_SENTRY_DSN` (web app) |
| Analytics (Google Tag Manager, PostHog) | See [Analytics](#analytics) | `NEXT_PUBLIC_GTM_ID`, `NEXT_PUBLIC_POSTHOG_KEY`, `ANALYTICS_OUTBOX_MODE=live` |
| Bank sync (Enable Banking) | The API and the worker, for the users who connect a bank | Each user's own Enable Banking key, added in Settings |
| Google sign-in | Browsers and the API, when a user chooses "Continue with Google" | `GOOGLE_CLIENT_ID` and `GOOGLE_CLIENT_SECRET` |
| Your identity provider (OIDC) | Browsers and the API, when a user chooses `Sign in with <name>`. The API fetches the provider's discovery document and keys, and exchanges the sign-in code | `OIDC_ISSUER`, `OIDC_CLIENT_ID` and `OIDC_CLIENT_SECRET` |
| reCAPTCHA | Browsers on the contact form, and the web app to check the answer | `NEXT_PUBLIC_RECAPTCHA_SITE_KEY` and `RECAPTCHA_SECRET_KEY` |

Browsers also load bank and exchange logos from the addresses stored in the bank and asset catalogue, and a merchant logo from the address a member typed in for it. The mobile app sends no analytics or error reports while it is connected to your server.
