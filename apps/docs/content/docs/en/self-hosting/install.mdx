## Install with the script

```sh
curl -fsSLO https://github.com/wondermoney/wondermoney/releases/latest/download/install.sh
curl -fsSLO https://github.com/wondermoney/wondermoney/releases/latest/download/install.sh.sha256
sha256sum -c install.sh.sha256
sh install.sh
```

The script checks for Docker, the Compose plugin, `openssl` and `curl`, and stops with instructions if one is missing. It downloads the server files from the release tag, writes `.env` with fresh secrets, starts the stack and waits up to three minutes for the API. It asks for the web app and API address; `--yes` takes the defaults, `http://localhost:3000` and `http://localhost:3001`. Run it again to upgrade: it never rewrites `.env`, and offers to move to the latest release.

It installs into `./wondermoney` (`--dir` picks another folder, `--version` another release) and sets `WM_VERSION` in `.env` to the release it installed. Run the `docker compose` commands on these pages from that folder. On macOS, check the download with `shasum -a 256 -c install.sh.sha256` instead of `sha256sum`.

### Read it first

The installer is a short POSIX `sh` script. Download it, read it, then run it:

```sh
curl -fsSLO https://github.com/wondermoney/wondermoney/releases/latest/download/install.sh
less install.sh
sh install.sh
```

Or do the same steps by hand, from the release tag:

```sh
# v1.14.0 here: the release you want
git clone --depth 1 --branch v1.14.0 https://github.com/wondermoney/wondermoney.git
cd wondermoney/apps/api/deploy/selfhost
./generate-env.sh
docker compose up -d
```

`generate-env.sh` writes a `.env` file with fresh secrets. It runs once: if `.env` already exists it stops without changing it, because new secrets would end existing sessions and make stored bank credentials unreadable. Keep `.env` safe, with your backups.

On the first start, the API creates the database and loads the reference data (currencies, categories and the asset catalogue). This takes a minute or two. To follow it:

```sh
docker compose logs -f api
```

## Create your account

Open http://localhost:3000. A new server opens on its setup page: create the first account there. The first account is the instance admin: it owns the server, can invite other people and can open the admin pages, such as [bank sync health](/en/docs/self-hosting/bank-sync-health). Once it exists, you continue with the usual first steps in the app.

<Callout type="warn" title="Finish setup before the server is reachable from the internet">
  Until the first account exists, whoever opens the app first becomes this server's admin. Create it on your own network, then add [HTTPS and a domain](/en/docs/self-hosting/https-and-domains).
</Callout>

After the first account, `SIGNUP_MODE` in `.env` decides who else can sign up:

| Value | Who can sign up |
|---|---|
| `open` | Anyone who can reach the web app |
| `invite` | Only people invited to a household |
| `closed` | Nobody; existing accounts keep working |

## Before you set up email

Until an email provider is configured, emails are not sent. They are written to the API log, links included. To reset a password or accept an invite in the meantime:

```sh
docker compose logs api | grep "Email not sent"
```
