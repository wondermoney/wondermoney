---
title: Import transactions from CSV
description: Import transaction history from a CSV file when bank sync is not available.
---

CSV import brings a bank statement into an account when a bank connection is not available, or adds history from before the connection started.

## Before you start

What the file looks like depends on the account's financial institution:

- **Millennium BCP, ActivoBank, Bankinter, Banco BPI or Montepio**: import the bank's own statement export (CSV or Excel), as the bank exported it. The account must have that bank as its financial institution; choose it when you add the account (**Add account**, then **Unlinked**).
- **Any other bank, or an account without a financial institution** (such as one made with **Add an account manually**): import a CSV file in the generic format below.

On a self-hosted instance, imports also need [file storage](/en/docs/self-hosting/configure#file-storage).

### Generic CSV format

The first row names the columns, and the file has these columns and no others:

| Column | Required | What goes in it |
|---|---|---|
| `date` | Yes | The date, as `YYYY-MM-DD`. |
| `amount` | Yes | An amount with a dot for decimals, such as `23.40`. For most types the type says whether the money left or arrived, so the sign doesn't matter. Exchange and Revert have no direction of their own: write money that left the account as a negative amount, such as `-23.40`, and money that arrived as a positive one. |
| `merchant` | Yes | Who you paid, or who paid you. |
| `internalTransactionId` | Yes | A unique ID for the row. A row whose ID was already imported into this account is skipped, so importing the same file twice adds nothing. |
| `transactionTypeKey` | Yes | The type's code. The import dialog lists the codes, such as Payment or Card payment for money out and Deposit or Transfer (in) for money in. |
| `description` | No | A note for the transaction. |

The import dialog shows these columns for a generic account and has a **Download template** button with two example rows that use your instance's type codes.

```csv
date,amount,merchant,internalTransactionId,transactionTypeKey,description
2026-01-15,23.40,Grocery store,example-1,3,Weekly shop
```

On a new instance code `3` is usually Payment; use the codes your dialog lists.

## Steps

1. Get the file ready: for a supported bank, download the statement as CSV or Excel (`.xlsx`) and leave it as the bank exported it; otherwise save your transactions as a CSV in the generic format.
2. Open the account and choose **Import transactions**.
3. Add the file (up to 5 MB) and choose **Import**.
4. The import runs in the background. A notification tells you when it has finished, or why it failed. If some rows of a generic file couldn't be imported, the dialog says how many.

## Review

After import, compare the number of rows and the first few balances with the source file. If the file covers a long period, check that the dates were interpreted correctly.

Imported rows are categorized using the same deterministic categorizer as synced transactions, so the reason you see on a suggestion is consistent no matter how the transaction arrived. When you bulk-categorize imported rows, the chosen category is written to each transaction and the merchant mapping is updated for future imports.

## Common issues

- The file uses an unexpected date format.
- Amounts are stored with the wrong decimal separator.
- Credits and debits are reversed.
- The same data was already imported from another source.
