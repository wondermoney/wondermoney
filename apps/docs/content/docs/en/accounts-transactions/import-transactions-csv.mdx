---
title: Import transactions from CSV
description: Import transaction history from a CSV file when bank sync is not available.
---

CSV import brings a bank statement into an account when a bank connection is not available, or adds history from before the connection started.

## Before you start

Any bank's statement export works, as CSV (any delimiter) or Excel (`.xls`, `.xlsx`). Download it from your bank's website and leave it as the bank wrote it: rows above the column names and totals below the transactions are fine.

For Millennium BCP, ActivoBank, Bankinter, Banco BPI and Montepio, WonderMoney reads the bank's own format when the account has that bank as its financial institution. For every other file, it finds the date, description and amount columns from their names, and works out the date format and the decimal separator from the values. When the names don't settle it, an AI model is asked which column is which: it sees the column names and what kind of values each column holds (dates, numbers, text), never your descriptions, amounts or dates. That uses one of your household's daily CSV mapping calls; on an instance without AI, or once the day's calls are used, you pick the columns yourself.

A file in the older WonderMoney CSV template (with `internalTransactionId` and `transactionTypeKey` columns) still imports as before.

On a self-hosted instance, imports also need [file storage](/en/docs/self-hosting/configure#file-storage).

## Steps

1. Download the statement from your bank as CSV or Excel.
2. Open the account and choose **Import transactions**.
3. Add the file (up to 5 MB). WonderMoney reads it straight away and shows how many transactions it found, the dates they cover, and the first few rows.
4. Check the rows. If a column is wrong, open **Adjust columns** and pick the right one, or change the date format, the number format, or whether spending is shown as a positive amount (as on some credit card statements). The preview updates as you change them.
5. Choose **Review transactions**. WonderMoney reads every row of the file and lists them, with nothing imported yet:
   - **New**: not in the account yet. These are included.
   - **Already in the account**: the same transaction was imported before, from this file or an overlapping export. These are skipped.
   - **Couldn't be read**: a row whose date or amount could not be read, with the reason. These never import.
6. Check the list. Untick a row to skip it, or tick one to include it. Show one kind of row and choose **Include all** or **Skip all** to decide them together.
7. Choose **Import**, which shows how many transactions it will add. The import runs in the background and shows its progress. If it stops part way (for example, the server restarts), choose **Try again**: it carries on from where it stopped, and nothing is imported twice.

A file that holds several accounts asks which of your accounts each one goes to before it can be imported.

An import you don't finish expires after seven days. Seven days after an import, WonderMoney deletes the file you uploaded and its row-by-row list; the import keeps only how many transactions were imported and skipped, and the imported transactions stay in the account. In the mobile app the import runs in one step: new transactions are imported and the ones already in the account are skipped.

## Review

After import, compare the number of rows and the first few balances with the source file. If the file covers a long period, check that the dates were interpreted correctly.

Imported rows are categorized using the same deterministic categorizer as synced transactions, so the reason you see on a suggestion is consistent no matter how the transaction arrived. When you bulk-categorize imported rows, the chosen category is written to each transaction and the merchant mapping is updated for future imports.

## Common issues

- The file uses an unexpected date format.
- Amounts are stored with the wrong decimal separator.
- Credits and debits are reversed.
- The same data was already imported from another source.
