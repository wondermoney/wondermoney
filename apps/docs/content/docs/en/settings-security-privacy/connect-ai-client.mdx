---
title: Connect an AI client
description: Let ChatGPT, Claude Desktop, Cursor or another MCP client ask about your own finances, read-only.
---

WonderMoney runs a read-only [Model Context Protocol](https://modelcontextprotocol.io) (MCP) server. An MCP client such as Claude Desktop, Cursor or VS Code can ask it about your accounts, spending, budgets, goals, net worth and portfolio, and answer in the client's own chat.

The server is at `POST /v1/mcp` on your API. It is not a separate account and it has no write tools: it can read and, if you allow it, propose a change for you to confirm. It never changes anything itself.

## What the client can see

The client sees exactly what you see:

- The household's shared accounts, transactions, budgets, categories, goals and portfolios.
- Your own private accounts and the private accounts shared with you, and **not** a household member's private accounts that are hidden from you.
- Never another household's data.

Every tool takes your identity from the token, or from the OAuth connection you allowed, so the same privacy rules that apply in the app apply here.

## What the client can do

The client can call these read-only tools:

- `get_account_balance_summary`, `list_accounts`, `get_net_worth_summary`
- `get_cashflow_summary`, `get_spending_by_category`, `get_spending_trend`, `get_large_transactions_summary`
- `search_transactions` (date range, account, category, amount range, up to 100 rows)
- `get_budget_status`, `compare_budget_periods`, `list_budgets`, `list_categories`
- `get_goal_progress_summary`, `get_recurring_payments_summary`
- `get_portfolio_summary`, `get_portfolio_income_summary`
- `get_insights`

It cannot create, change or delete anything, and it cannot reach the household, bank connections, exports or token management.

## Proposals

With the proposals scope (`mcp:propose`), the client can also call `propose_categorize_transactions`, `propose_mark_transactions_reviewed` and `propose_update_transaction_note`. Each one checks that every transaction is one you can see and drafts a proposal; it does not change the transaction. The proposal waits in **Settings > Assistant > Pending changes** (and **More > Pending changes** on mobile) until you apply or dismiss it, and expires after seven days. The client cannot apply it, and no API token can. See [Assistant settings](/en/docs/settings-security-privacy/assistant-settings#proposals-and-pending-changes).

## Create a token

1. Open **Settings → API tokens**.
2. Under **Connect an AI client**, select **Create an AI client token**.
3. Copy the token immediately. It is shown once.

The shortcut creates a token named "AI client" with the **AI client (MCP)** scope and a 90-day expiry. If you use two-factor authentication, enter your authenticator code first. Tick **Let the client propose changes for me to confirm** first to add the proposals scope. You can also create the token by hand in the form above, choosing the same scopes.

The `mcp:read` and `mcp:propose` scopes reach only the MCP endpoint: `mcp:read` exposes the read-only tools and `mcp:propose` the proposal tools. It does not grant the ordinary data routes, and a `read` token does not reach MCP: the two are separate credentials on purpose.

## Client configuration

Claude Desktop bridges a remote MCP server with `mcp-remote`. Add this to its `claude_desktop_config.json`:

```json
{
  "mcpServers": {
    "wondermoney": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "https://api.example.com/v1/mcp",
        "--header",
        "Authorization: Bearer <your-token>"
      ]
    }
  }
}
```

Cursor and other clients that speak Streamable HTTP directly use the URL and header form:

```json
{
  "mcpServers": {
    "wondermoney": {
      "url": "https://api.example.com/v1/mcp",
      "headers": {
        "Authorization": "Bearer <your-token>"
      }
    }
  }
}
```

Replace the API address with your own and `<your-token>` with the value you copied. The endpoint is stateless: the client sends the token on every request, and there is no session to keep.

## Connect ChatGPT

ChatGPT, and other clients that sign in with OAuth, connect without a token, on a server that offers it (see [Self-hosting](#self-hosting)). Settings then shows **Connect ChatGPT** under **Connect an AI client**.

1. In ChatGPT, add an app (a connector) and give it the MCP endpoint, `https://api.example.com/v1/mcp` with your API address, and choose OAuth.
2. ChatGPT sends you to WonderMoney. Sign in if you are not signed in already, with your second factor if you use one.
3. The consent page names the client, the address it sends you back to and your household, and lists what it may do. Select **Allow**.

The client gets read access only (`mcp:read`): the read-only tools above, never the proposal tools, which stay behind a personal token. It stays connected until you disconnect it; its access token lasts 15 minutes and is renewed without asking you again. Clients you allowed are listed under **Connected with OAuth**, with when they last called a tool.

Check the address on the consent page before you allow: any client can register itself under any name, and only the address it sends you back to (such as `chatgpt.com`) says where your answer goes.

## Audit log

Every tool call is written to the assistant audit log with the tool name, the token or OAuth client, and the time. Amounts and descriptions are never written there. **Settings → API tokens → Connect an AI client** lists the most recent calls.

## Revoke access

Select **Revoke** next to the token in **Settings → API tokens**. Revocation is immediate: the next request from the client gets `401 Unauthorized`. Delete the server entry from the client's configuration as well, so it stops retrying.

For a client connected with OAuth, select **Disconnect** next to it under **Connected with OAuth**. Its tokens stop working at once, and its next request gets `401 Unauthorized`. To use it again, connect it again from the client.

## Rate limits

MCP traffic uses the token's own request budget, and each token may make a limited number of tool calls per minute (60 by default). A client over either limit gets an error and can retry shortly. The budget is separate from your browser session.

## Self-hosting

The server is on by default. Set `MCP_ENABLED=false` on the API to turn it off: `POST /v1/mcp` then answers `404`, and `GET /v1/instance` reports `features.mcp: false`, so the settings panel disappears. See [Configure](/en/docs/self-hosting/configure).

OAuth, which ChatGPT needs, is off by default. Set `MCP_OAUTH_ENABLED=true` on the API to offer it. It needs an `https` `API_URL`, and it lets any client register itself, as MCP clients expect; each still needs a person's consent. With it on, the API serves the discovery documents at `/.well-known/oauth-protected-resource` and `/.well-known/oauth-authorization-server`, and a `401` from `POST /v1/mcp` points the client at them. On one hostname, route `/.well-known/oauth-*` to the API as well; the bundled proxy does.
