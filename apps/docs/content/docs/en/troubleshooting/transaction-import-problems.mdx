## Symptoms

- An import file is rejected.
- The import finishes but transactions do not appear.
- Some rows are skipped.
- Dates, amounts, or descriptions look wrong after import.

## What to check

- Whether the file format matches the import tool.
- Whether the column headers and separators are correct.
- Whether the file includes duplicate or blank rows.
- Whether the account and date range match the data you want.

## What to try

1. Re-export the file from the source system if possible.
2. Remove duplicate rows and empty lines.
3. Check the column mapping before confirming the import.
4. Try a smaller file to isolate the problem.

## Similar transactions and duplicates

WonderMoney recognises a file row as already imported by the bank's own id or reference when the file has one (an OFX `FITID`, a CAMT.053 reference), and otherwise by a fingerprint built from details such as its date and amount. Rows of the same file that share those details are counted separately, so two purchases of the same amount on the same day both import. A row imported before is listed in the review as **Already in the account** and skipped unless you include it; the transaction in the account is left as it is.

A file row with the same amount as a transaction already in the account, up to 3 days apart, is listed in the review as a possible duplicate, beside the transaction it resembles. It is skipped unless you include it; see [Possible duplicates](/en/docs/accounts-transactions/import-transactions-csv#possible-duplicates).

For more on how transactions are matched and stored, see [Understand transactions](/en/docs/accounts-transactions/understand-transactions).

## When to contact support

Contact support if the file follows the required format but imports still fail, or if the import creates incorrect transactions that you cannot correct manually.
